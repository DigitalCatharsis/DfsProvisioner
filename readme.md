# DFS Provisioner

**DFS Provisioner** – WPF-приложение для автоматизации создания SMB-шар, настройки NTFS-прав, групп Active Directory и DFS-ссылок. Программа позволяет выполнить все операции одной кнопкой или по шагам, используя настраиваемый JSON-конфиг и понятный интерфейс с цветным логом.



## Возможности

- **Создание двух групп в Active Directory** (чтение/запись) с указанием OU, описания и заметок.
- **Создание файловой папки** на удалённом сервере (через WMI), расшаривание папки и настройка разрешений шары (SMB).
- **Настройка NTFS-прав** – удаление Everyone, добавление групп с ReadExecute/Modify.
- **Создание DFS-ссылки** и добавление целевого UNC-пути.
- **Живые превью** – отображают расположение групп в AD, UNC-путь к шаре и финальный DFS-путь.
- **Цветной лог** с временными метками – ошибки красным, информационные сообщения белым.
- **Поддержка трёх независимых учётных записей:** AD, файловый сервер, DFS (пароли хранятся в `SecureString`).
- **Идемпотентность** – повторные запуски не создают дубликатов; перед добавлением прав удаляются старые ACE для этих же SID.

## Системные требования

- **Windows 10/11** или **Windows Server 2016+** с установленным .NET 9 Desktop Runtime (x64).
- **PowerShell 7** или **Windows PowerShell 5.1** (для DFS-операций требуется модуль `DFSN`, входящий в RSAT).
- **Права:**
  - AD-учётная запись – создание групп в целевом OU.
  - Серверная учётная запись – локальный администратор на файловом сервере.
  - DFS-учётная запись – права на управление пространством имён DFS.

# Установка и запуск

1. Скачайте последний релиз (`DFS_Provisioner.exe`, `appsettings.json`, `System.Management.Automation.dll` при необходимости) или соберите проект самостоятельно.
2. Поместите все файлы в одну папку.
3. Настройте конфигурационный файл `appsettings.json` (см. раздел «Конфигурация»).
4. Запустите `DFS_Provisioner.exe`.
5. При необходимости введите учётные данные на вкладке **Credentials**.
6. Нажмите **1. Check all** для проверки окружения, затем выполняйте шаги по порядку или кнопку **Run all**.

# Конфигурация (appsettings.json)

```json
{
  "Credentials": {
    "ADUsername": "contoso.com\\svc_ad",
    "ServerUsername": "contoso.com\\svc_share",
    "Server": "fs01.contoso.com.com",
    "DFSUsername": "contoso.com\\svc_dfs"
  },
  "ActiveDirectory": {
    "Domain": "contoso.com",
    "GroupsOU": "OU=ProjectGroups,DC=contoso,DC=com",
    "ReadGroupName": "",
    "WriteGroupName": "",
    "GroupDescriptionTemplate": "{ShareName} – {AccessType} access",
    "GroupNotesTemplate": "Created by DFS Provisioner on {Date}"
  },
  "Share": {
    "LocalPath": "E:\\Shares\\MyShare",
    "OwnerAccount": "DOMAIN\\svc_ad"
  },
  "DFS": {
    "NamespaceRoot": "\\\\contoso.com\\DFSroot",
    "LinkNameTemplate": "work\\{ShareName}"
  },
  "Options": {
    "ADReplicationWaitSeconds": 5
  }
}
```

* **Credentials** – логины (не храните пароли в конфиге). Поле **Server** – DNS-имя файлового сервера.
* **ActiveDirectory** – если `ReadGroupName`/`WriteGroupName` пусты, имена сгенерируются как `{ИмяПапки}_Read` / `{ИмяПапки}_Write`.
* `{ShareName}` в шаблонах заменяется на имя папки из `LocalPath`.
* **DFS** – `NamespaceRoot` и `LinkNameTemplate` формируют итоговый DFS-путь.
* **Options** – `ADReplicationWaitSeconds` задаёт паузу после создания групп (ожидание репликации).

# Описание интерфейса


| Вкладка | Назначение |
| :--- | :--- |
| Credentials | Домен, сервер, учётные данные (AD, файловый сервер, DFS) |
| AD Groups | OU, имена групп, шаблоны описания/заметок, превью расположения групп |
| Share and NTFS | Локальный путь, автоматическое имя шары, UNC-превью, владелец, удаление Everyone |
| DFS | Корень пространства имён, шаблон ссылки, превью итогового DFS-пути и цели |
| Log | Цветной лог операций |

# Принцип работы

* **Check all** – проверяет подключение к файловому серверу, существование групп AD, шары и DFS-ссылки.
* **Create AD groups** – создаёт группы в указанном OU с описанием и заметками (если не существуют).
* **Create share and NTFS** – создаёт папку и шару, настраивает разрешения SMB (Read/Change для групп) и NTFS.
* **Setup DFS** – создаёт DFS-ссылку и добавляет целевой UNC-путь.
* **Run all** – выполняет все шаги последовательно.

Все операции идемпотентны: если объект уже существует, он пропускается; перед добавлением новых прав удаляются старые ACE для соответствующих SID.

# Учётные записи и права

* **AD-учётная запись** – создаёт группы, читает SID.
* **Серверная учётная запись** – администратор файлового сервера (WMI доступ, создание папок/шар, настройка разрешений).
* **DFS-учётная запись** – права на управление пространством имён DFS (используется PowerShell процесс под этой учёткой).

Пароли передаются в WMI и PowerShell в виде `SecureString` без явного преобразования в строку.

# Логирование

* Лог отображается на вкладке **Log** в реальном времени.
* Ошибки выделяются красным, информационные сообщения – белым.
* Все записи снабжены временными метками.
